# Git Workflow Project

## Introduction

This project demonstrates the basic Git workflow used to manage and share files in a software development project.

Git is a version control system that allows developers to track changes, maintain different versions of their work, and collaborate with other developers.

## Project Goals

The main goals of this project are:

- Create and manage files using Git.
- Track changes made to files.
- Save changes using commits.
- Connect a local repository to GitHub.
- Push changes from the local repository to a remote repository.
- Understand the basic Git workflow.

## Basic Git Workflow

The main Git workflow used in this project is:

1. **Edit** – Create or modify a file.
2. **Add** – Stage the changes using `git add`.
3. **Commit** – Save the staged changes using `git commit`.
4. **Push** – Upload the commits to GitHub using `git push`.

## Why Git Makes Development Easier

Git makes development easier because it keeps track of the changes made to a project over time.

First, Git helps **safeguard code**. Instead of having only one version of a project, developers can save different versions using commits. If something goes wrong, they can look at previous versions and recover their work.

Second, Git **tracks project history**. Every commit records what changes were made and when they were made. This makes it easier to understand how a project developed and to find when a problem was introduced.

Finally, Git makes **team collaboration** easier. Multiple developers can work on the same project, share their changes through a remote repository such as GitHub, and keep their work organized.

For these reasons, Git is an important tool for managing software projects and working efficiently with other developers.
